## 1. 报表说明

达人带货订单明细报表。回答「某个时间段内哪些达人出了多少单、卖了多少钱、卖的是什么」。
数据来自达人订单主表 `t_daren_order`，每行一个订单行。每日 06:00 全量刷新，数据延迟 T+1
（今天能看到截至昨天完整日的数据）。数据范围自 2026-01-01 起，更早的在归档表，本报表不含。

## 2. 适用问题

- "上个月张三的达人订单明细"
- "7 月 1 号到 15 号哪些达人出单了"
- "帮我导一下最近的达人订单"
- "达人订单报表"、"达人出单数据"、"带货订单明细"
- "某个网红这段时间卖了多少"
- "哪些达人有订单"、"出单量排行"
- "按天统计一下达人出单"
- "把这个月的达人订单给我导出成 Excel"

**本报表不覆盖**：

- 结算金额、佣金、打款账单 —— 见《达人结算报表》
- 商品库存与销量（非达人维度）—— 见《商品销量报表》
- 达人入驻资料、签约状态 —— 见《达人档案》
- 退货退款工单流程 —— 见《售后工单报表》

## 4. 表结构

### 4.1 `t_daren_order`

| 字段 | 类型 | 含义 | 口径 / 枚举 | 备注 |
| --- | --- | --- | --- | --- |
| order_id | bigint | 订单号 | 唯一，一个订单一行 | 长数字，导出时须按文本写，否则 Excel 会显示成科学计数法 |
| order_time | datetime | 下单时间 | 时区 Asia/Shanghai | 本报表的时间基准 |
| influencer_id | varchar | 达人 ID | 达人唯一标识 | 为空代表非达人渠道订单 |
| influencer_name | varchar | 达人昵称 | 展示名，可能重名 | 按昵称筛选时需注意重名 |
| product_name | varchar | 商品名称 | — | |
| shop_name | varchar | 所属店铺 | — | |
| quantity | int | 购买数量 | 件数 | |
| pay_amount | decimal(12,2) | 支付金额 | 单位**元**，含税，不含运费 | 已扣优惠券 |
| order_status | varchar | 订单状态 | `paid` 已支付 / `pending` 待支付 / `closed` 已关闭 | 只有 `paid` 计入成交 |
| refund_status | varchar | 退款状态 | `none` 无退款 / `refunding` 退款中 / `refunded` 已退款 | |

## 5. 字段口径与陷阱

- **金额**：`pay_amount` 单位是**元**（不是分），含税、不含运费，已扣优惠券。
  求和即为支付总额，无需再乘 100。
- **一行代表什么**：一个订单行。同一个 `order_id` 目前只会出现一行；
  若后续引入子订单会变成多行，届时需按 `order_id` 去重。
- **有效订单**：`order_status = 'paid'` 且 `refund_status != 'refunded'`。
  **待支付（`pending`）和已关闭（`closed`）不计入销售额**——这是最容易算错的地方，
  直接用 `SUM(pay_amount)` 不过滤会把待支付也算进去。
- **退款处理**：`refunding`（退款中）**仍计入**（钱还没退，业务口径按在途处理）；
  `refunded`（已退款）排除。
- **NULL 语义**：`influencer_id` 为空代表非达人渠道订单，本报表默认不排除，
  如需只看达人订单可加 `influencer_id IS NOT NULL`。
- **时区**：库里存的是东八区时间，无需换算。
- **已知脏数据**：`shop_name = '测试店铺'` 是联调测试单，需排除。

## 6. 参数契约

日期区间统一**左闭右开**：`[:start_date, :end_date)`。

| 参数名 | 类型 | 必填 | 默认 | 自然语言说法示例 | 归一化规则 |
| --- | --- | --- | --- | --- | --- |
| `:start_date` | datetime | 是 | — | "上月"、"7月1日到7月15日"、"最近7天"、"上个月" | 解析为 Asia/Shanghai 自然日的 00:00:00，含当日 |
| `:end_date` | datetime | 是 | — | 同上 | 取用户所说**结束日期的次日** 00:00:00，不含当日。例："7月1日到7月15日" → `:start_date`=2026-07-01 00:00:00、`:end_date`=2026-07-16 00:00:00 |
| `:influencer` | string | 否 | NULL（全部达人） | "张三"、"达人张三"、"达人号 D001" | 按 `influencer_name` **精确匹配**；传 NULL 表示不限达人。若用户给的是达人 ID，请改用 `influencer_id` 条件或在回答里说明只支持昵称 |

**日期归一化补充说明**：

- "上月" / "上个月" → 上一个自然月的 1 日 00:00:00 到本月 1 日 00:00:00
- "最近 7 天" → 今天往前 7 个自然日（不含今天），即 `[今天-7天 00:00, 今天 00:00)`
- "本月" / "这个月" → 本月 1 日 00:00:00 到下一月 1 日 00:00:00
- 用户只给了一个日期（如"7 月 5 号"）→ 按单日处理：`[7月5日 00:00, 7月6日 00:00)`
- **换算结果必须在回答里复述**，让用户能核对

## 7. 查询模板

### 7.1 查询某达人某时间段的订单明细

**用途**：用户要看/要导出订单逐行明细，或指定了某个达人。默认场景。
**使用参数**：`:start_date`、`:end_date`、`:influencer`
**输出列**：

| 列名 | 中文表头 | 格式 | 说明 |
| --- | --- | --- | --- |
| order_id | 订单号 | 文本 | 长数字，必须按文本写 |
| order_time | 下单时间 | 日期时间 | |
| influencer_id | 达人ID | 文本 | |
| influencer_name | 达人 | 文本 | |
| product_name | 商品 | 文本 | |
| shop_name | 店铺 | 文本 | |
| quantity | 数量 | 数字 | |
| pay_amount | 支付金额 | 数字 | 单位元 |
| order_status | 订单状态 | 文本 | |
| refund_status | 退款状态 | 文本 | |

```sql
-- 达人订单明细
SELECT
    order_id,
    order_time,
    influencer_id,
    influencer_name,
    product_name,
    shop_name,
    quantity,
    pay_amount,
    order_status,
    refund_status
FROM t_daren_order
WHERE order_time >= :start_date
  AND order_time <  :end_date
  AND (:influencer IS NULL OR influencer_name = :influencer)
  AND shop_name <> '测试店铺'
ORDER BY order_time
```

### 7.2 按达人统计出单量与销售额

**用途**：用户问"哪些达人出单多""出单量排行""各达人卖了多少"，要的是汇总而不是明细。
**使用参数**：`:start_date`、`:end_date`

```sql
-- 达人维度汇总
SELECT
    influencer_name,
    COUNT(*)          AS order_count,
    SUM(quantity)     AS total_quantity,
    SUM(pay_amount)   AS total_amount
FROM t_daren_order
WHERE order_time >= :start_date
  AND order_time <  :end_date
  AND order_status = 'paid'
  AND refund_status <> 'refunded'
  AND shop_name <> '测试店铺'
GROUP BY influencer_name
ORDER BY total_amount DESC
```

**输出列**：

| 列名 | 中文表头 | 格式 | 说明 |
| --- | --- | --- | --- |
| influencer_name | 达人 | 文本 | |
| order_count | 订单数 | 数字 | 已按有效订单过滤 |
| total_quantity | 总数量 | 数字 | |
| total_amount | 总金额 | 数字 | 单位元 |

> 注意：本模板**已内置有效订单过滤**（`paid` 且非 `refunded`），编排层不要再叠加。

### 7.3 按天统计订单量与销售额

**用途**：用户问"每天的出单情况""日趋势""按天统计"。
**使用参数**：`:start_date`、`:end_date`
**输出列**：

| 列名 | 中文表头 | 格式 | 说明 |
| --- | --- | --- | --- |
| order_date | 日期 | 日期 | |
| order_count | 订单数 | 数字 | |
| total_amount | 总金额 | 数字 | 单位元 |

```sql
-- 按天汇总
SELECT
    DATE(order_time)  AS order_date,
    COUNT(*)          AS order_count,
    SUM(pay_amount)   AS total_amount
FROM t_daren_order
WHERE order_time >= :start_date
  AND order_time <  :end_date
  AND order_status = 'paid'
  AND refund_status <> 'refunded'
  AND shop_name <> '测试店铺'
GROUP BY DATE(order_time)
ORDER BY order_date
```
