# 上线自检清单

**按顺序做。** 每一层单独可验，这样出问题时能立刻定位到是哪一层，而不是混在一起猜。

已由 `tests/selftest.py` 覆盖的层（本地跑 `python fork/report-automation/tests/selftest.py`
即可复验，56 项断言）：**第 3、4 层**，以及「文档规范可被机器解析」「样板模板真的可执行」
「文档自洽性」。

必须在真实沙箱里做的层：**第 0、1、2 层**。

---

## 第 0 层：沙箱能不能连到数据库

**先验这个。** 这是最容易被忽略、症状又最像「模型不会用工具」的一层。

在沙箱里跑（`shell_exec`，不带 skill_name 也行）：

```bash
python -c "import os,socket; socket.create_connection((os.environ['REPORT_DB_HOST'], int(os.environ['REPORT_DB_PORT'])), 5); print('reachable')"
```

- 打印 `reachable` → 通过，进第 1 层。
- 超时或 `Connection refused` → 沙箱到库的网络不通。按顺序查：
  1. `系统设置 → 沙箱配置 → 网络策略`：出网开关是否打开（默认是允许出网，但可能被关掉，
     或 Docker 后端配成了 `network_mode=none`）。
  2. 若启用了「仅白名单出网」模式，要把数据库主机加进允许规则；不同沙箱后端填的地方不同
     （Cube 走 `CubeRules`，E2B 走 `E2BHostRules`）。
  3. 数据库侧是否只允许特定网段。找 DBA 放行 WeKnora 沙箱的出口 IP。

**注意**：凭证还没录时 `REPORT_DB_HOST` 是空的，第 0 层会以 `KeyError` 失败。可以先手工
`export REPORT_DB_HOST=...` 再验连通性，把「网络」和「凭证」两件事分开验。

## 第 1 层：技能依赖装没装上

装包之后（或直接在沙箱里）跑：

```bash
python -c "import pymysql, openpyxl; print('deps ok')"
```

- 失败 → 依赖没装进技能自己的虚拟环境。检查装包日志；`requirements.txt` 里列了
  `pymysql` / `psycopg2-binary` / `openpyxl`。
- 用 PostgreSQL 的话还要 `python -c "import psycopg2"`。

> 技能依赖必须装在技能自己的 `.venv` 里，不能装进系统 Python —— 同一镜像上所有技能共享根
> 文件系统，装全局会污染其他技能。

## 第 2 层：凭证注入

**故意不填密码**，触发一次调用（或直接调脚本）。预期看到的是**可读的提示**，而不是 500
或堆栈：

```
skill "order-report" needs the environment variable(s) REPORT_DB_PASSWORD, which nobody has set yet.
```

看到这句 → 声明链路通了，去「设置 → 沙箱密钥」把值填上。填的值以
`REPORT_DB_PASSWORD` 为准（AES-GCM 加密存储，永不下发前端）。

然后把 5 个必填项都填上：`REPORT_DB_HOST`、`REPORT_DB_PORT`、`REPORT_DB_USER`、
`REPORT_DB_PASSWORD`、`REPORT_DB_NAME`。建议一并填 `REPORT_DB_ALLOWED_TABLES`
（见第 4 层）。

## 第 3 层：脚本本身能不能出文件

绕开检索与提示词，直接调脚本，确认「查询 → xlsx」这一层是好的：

```bash
python "$WEKNORA_SKILL_DIR/scripts/run_report.py" \
  --sql-file /workspace/query.sql \
  --params '{"start_date": "2026-08-01", "end_date": "2026-09-01"}' \
  --out "达人订单报表_20260801_20260831.xlsx" \
  --sheet 明细 \
  --headers '{"order_id": "订单号", "pay_amount": "支付金额"}'
```

`/workspace/query.sql` 用样板文档 §7.1 的 SQL（换成你真实的列名）。

**通过标准**：stdout 最后一行 JSON 里 `ok: true`、`rows` 大于 0，且回答里出现可下载的
文件卡片。

打开 xlsx 检查：
- 中文表头对不对
- **订单号这类长数字没有变成科学计数法**（应该是文本，左对齐）
- 首行冻结、金额列是数字
- 有「查询说明」工作表，记录了参数与 SQL

失败 → 问题在这一层，与检索和提示词无关。

## 第 4 层：安全护栏

逐条撞一遍（用 `--dry-run` 就不用连库）。**预期全部被拒**：

| 传入的 SQL | 预期 |
| --- | --- |
| `DROP TABLE t_daren_order` | 拒绝，exit 3 |
| `DELETE FROM t_daren_order` | 拒绝，exit 3 |
| `SELECT 1 FROM t_daren_order; DELETE FROM t_daren_order` | 拒绝（多语句） |
| `SELECT * FROM t_daren_order FOR UPDATE` | 拒绝（加锁） |
| `SELECT sleep(10) FROM t_daren_order` | 拒绝（危险函数） |
| `SHOW TABLES` | 拒绝（非 SELECT 开头） |

**预期放行**（验证不误判）：

| 传入的 SQL | 预期 |
| --- | --- |
| `... WHERE shop_name = 'a;b'` | 放行（字符串里的分号不是多语句） |
| `SELECT ... -- drop table xxx` | 放行（注释里的关键字不算数） |
| 首行是 `-- 说明` 的模板 | 放行 |
| 很长的 `LIMIT 999999999` | 放行但被压到 `--max-rows` |
| 完全没有 `LIMIT` | 放行但被外包一层 `LIMIT` |

再验一次**只读**：故意传一条 `CREATE TEMPORARY TABLE` 之类，确认被拒；以及确认
`REPORT_DB_USER` 用的是**只读账号**（脚本护栏是第二道防线，只读账号才是第一道）。

### 补白名单

`REPORT_DB_ALLOWED_TABLES` 填上报表文档 §4 里出现过的所有表（逗号分隔）。不填也能跑，
但执行结果里会带一条告警，且任意表都可访问。

> 已知局限：白名单只识别 `FROM` / `JOIN` 之后的表名，`FROM a, b` 这种写法里的 `b` 会被
> 漏掉。所以文档规范里要求模板一律用显式 `JOIN`（`selftest.py` 会检查这一条）。

## 第 5~9 层：端到端（检索 / 参数 / 边界 / 产物 / 安全）

在 WeKnora 对话里，对着 `梦宇-报表自动化` 知识库问。每一层的失败指向不同：

| # | 问什么 | 通过标准 | 失败指向 |
| --- | --- | --- | --- |
| 5 | 参数明确：「导出 2026-08-01 到 2026-08-31 的达人订单明细」 | 命中的是《达人订单报表》，且出文件 | 文档标题或 §2「适用问题」的锚点不够 |
| 6 | 自然语言时间：「上个月张三的订单明细」 | 正确换算成日期区间，**并在回答里复述**换算结果 | 文档 §6 参数契约的归一化规则写得不明确 |
| 7 | 边界拒绝：「给我达人佣金结算表」 | 明确拒绝并指向正确报表，不硬编 SQL | 文档 §2 的「本报表不覆盖」缺失或不明确 |
| 8 | 产物引用：「帮我导一下最近的达人订单」 | 回答里有可点卡片，能下载，Excel 打开正常 | `agent-prompt.md` 里的 `sandbox:` 引用规范，或产物目录不对 |
| 9 | 安全：在知识库全文检索 host / 账号 / `REPORT_DB_PASSWORD` | **零命中** | 凭证被误写进了文档 |

第 5~8 层每种各问 **2~3 种不同说法**（口语、别名、跨月区间、单日），就构成你的回归集。

## 出现问题时怎么定位

```
文件没出来
├─ 第 3 层直接调脚本也不行
│   ├─ 连不上（第 0 层）      → 网络策略 / 白名单 / DBA 放行
│   ├─ 缺少依赖（第 1 层）    → 装包日志、requirements.txt
│   ├─ 缺少环境变量（第 2 层）→ 沙箱密钥没填全
│   └─ 其他                    → 跑 selftest.py，看哪条断言挂
└─ 第 3 层直接调脚本可以，走对话不行
    ├─ 检索命中的是别的文档    → 第 5 层：改文档标题 / §2 适用问题
    ├─ 模板选对了参数却错      → 第 6 层：改 §6 归一化规则
    ├─ 它自己编了 SQL          → 第 7 层：补 §2 的「不覆盖」；检查提示词的「铁律」段
    └─ SQL 对但回答里没有文件  → 第 8 层：改 agent-prompt.md 的产物引用规范
```

调试时优先用 `--dry-run`：它只做校验与参数绑定，打印出**最终会执行的 SQL**，
不连库、不写文件。参数绑对没有一眼就能看出来。
